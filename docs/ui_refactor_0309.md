# UI 重构方案 - 2025-03-09

## 当前问题分析

### 现状
- **5个底部Tab**: 首页、运动、教程、身体、设置
- **首页**: 展示今日/本周统计、快速开始、教程入口
- **运动Tab**: 运动记录列表 + 筛选功能
- **存在信息重复**: 首页和运动Tab都有统计数据入口

### 痛点
1. 首页与运动Tab功能有重叠，用户需要在两个Tab间切换查看统计和记录
2. 底部5个Tab过于分散，单手操作不便
3. 首页布局较松散，信息密度低
4. 统计功能入口深，用户需要跳转才能查看详细统计

---

## 优化方案

### 方案一：紧凑整合型（推荐）

**核心思路**: 合并首页和运动Tab为统一的"运动"模块，底部简化为4个Tab

#### 底部导航调整
| 当前 | 优化后 |
|------|--------|
| 首页 | 运动（整合版） |
| 运动 | 教程 |
| 教程 | 身体 |
| 身体 | 设置 |
| 设置 | - |

#### 运动首页重构（合并后）

```
┌─────────────────────────────┐
│  ← 今日概览（紧凑）         │
│  ┌──────┐ ┌──────┐ ┌──────┐ │
│  │ 时长 │ │ 热量 │ │ 次数 │ │
│  └──────┘ └──────┘ └──────┘ │
├─────────────────────────────┤
│  ← 快速开始                 │
│  [跑步] [骑行] [走路] [健身]│
├─────────────────────────────┤
│  ← 最近记录                 │
│  • 跑步 - 3.2km - 25分钟    │
│  • 骑行 - 10km - 45分钟     │
│  • 健身 - 60分钟            │
│           查看全部 →        │
├─────────────────────────────┤
│  ← 本周数据（mini卡片）    │
│  本周累计: 120分钟 / 15km   │
└─────────────────────────────┘
```

#### 改动点
1. **顶部Tab合并**: 首页 → 运动首页（整合版）
2. **统计紧凑化**: 3个核心指标（时长/热量/次数）横向排列
3. **快速开始前置**: 运动类型选择放在统计下方
4. **最近记录**: 展示最近3条运动记录预览 + "查看全部"入口
5. **本周数据**: 简化为单行mini卡片，点击进入详细统计页

#### 优势
- 信息密度高，单屏展示完整运动概览
- 减少Tab切换，操作路径更短
- 快速开始按钮醒目，降低使用门槛

---

### 方案二：垂直整合型

**核心思路**: 首页保留但精简为"今日看板"，运动Tab强化记录功能

#### 底部导航（保持4个Tab）
| Tab | 功能 |
|-----|------|
| 首页 | 今日数据看板 + 快速开始 |
| 运动 | 运动记录列表 + 筛选 |
| 教程 | 健身教程 |
| 我的 | 身体数据 + 设置 |

#### 首页重构（精简版）

```
┌─────────────────────────────┐
│  你好！今天也要运动哦         │
│  3月9日 星期日               │
├─────────────────────────────┤
│  今日数据                    │
│  ┌─────────┐ ┌─────────┐    │
│  │ ⏱ 25min │ │ 🔥 200  │    │
│  │   时长   │ │  卡路里  │    │
│  └─────────┘ └─────────┘    │
├─────────────────────────────┤
│  今日运动  ▶                 │
│  跑步 · 3.2km · 25分钟       │
├─────────────────────────────┤
│  快速开始                    │
│  [跑步] [骑行] [走路] [健身]│
└─────────────────────────────┘
```

#### 运动Tab强化
- 保留筛选 + 列表功能
- 顶部添加统计汇总（本周/本月累计）
- 支持按日期分组显示

#### 优势
- 首页更清爽，聚焦"今日"
- 运动Tab保留完整记录管理功能
- Tab数量适中，职责清晰

---

## 推荐方案

**选择方案一（紧凑整合型）**，理由：
1. 减少用户认知负担，统计+记录一体化
2. 4个Tab更适合单手操作
3. 运动作为核心功能，应占据首页位置
4. 教程和身体数据作为模块独立辅助存在

## 实施建议

### Phase 1: 底部导航重构
- 移除首页Tab，改为运动Tab
- 路由调整: `/` → `/exercise`

### Phase 2: 运动首页开发
- 新建整合版运动首页组件
- 复用现有StatisticsProvider数据

### Phase 3: 细节优化
- 快速开始按钮增加动效
- 最近记录支持下拉刷新
- 本周数据卡片点击跳转统计页
